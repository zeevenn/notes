# 检索与重排

检索阶段需要从大量片段中找到能够支持当前回答的证据。它通常先以较低成本扩大召回范围，再用更精确但更昂贵的方法缩小候选集：

```text
问题 → 查询处理 → 多路召回 → 融合与去重 → 重排 → Top-K 证据
```

召回强调不要漏掉相关内容，重排强调让最相关内容排在前面。两者的目标不同，不应只用最终回答是否“看起来不错”来判断检索质量。

## 关键词检索

BM25（Best Matching 25）是一种基于词项匹配的排序函数。它考虑查询词在文档中的出现频率、词在整个语料中的稀有程度和文档长度。

关键词检索适合：

- 错误码、产品型号、版本号和工单编号。
- 人名、缩写和领域专有名词。
- 查询与文档使用相同词汇的场景。

它难以直接处理同义表达。例如查询“忘记密码”，文档只写“凭证恢复”时，纯关键词匹配可能漏掉相关内容。

## 向量检索

向量检索使用 Embedding 模型把查询和片段转换为向量，再根据余弦相似度、内积或欧氏距离寻找近邻。它能匹配表面用词不同但语义接近的内容。

向量相似不等于能够回答问题。查询“如何取消订单”可能召回大量关于订单流程的片段，却没有一条包含取消条件。模型选择、文档语言、文本长度和领域差异也会影响向量表示。

详见 [Embeddings](../llm-fundamentals/embeddings.md) 和[向量数据库](../llm-fundamentals/vector-databases.md)。

## 混合检索

混合检索同时执行关键词检索和向量检索，使精确词项与语义相似性互补：

```text
                 ┌→ BM25 Top-N ────┐
用户问题 ────────┤                  ├→ 排名融合 → 候选集
                 └→ Vector Top-N ──┘
```

两种检索返回的原始分数含义和取值范围不同，不能默认直接相加。常见融合方式是 RRF（Reciprocal Rank Fusion，倒数排名融合），只依赖每一路结果的排名：

```text
RRF 分数(document) = Σ 1 / (k + rank_i(document))
```

`rank_i` 是文档在第 `i` 路结果中的名次，`k` 是降低头部名次差异影响的常数。另一种方式是先校准或归一化不同分数，再按业务权重合并；这需要用评估集验证。

## 查询处理

用户问题不一定能直接用于检索。多轮对话中的“那试用期呢？”缺少检索所需的主体，需要结合对话改写为独立问题，例如“试用期员工的年假天数是多少？”

常见处理包括：

- **查询规范化**：统一大小写、全半角、日期和产品编号格式。
- **对话消歧**：补齐代词、主体和前文限定条件。
- **同义词扩展**：同时搜索“年假”“带薪休假”等领域表达。
- **查询分解**：把需要多个事实的问题拆成若干子查询。
- **查询路由**：根据问题类型选择制度索引、代码索引或结构化数据库。

查询改写可能改变原意。系统应保存原始问题和改写结果，限制改写次数，并使用包含歧义问题的评估集验证。

## 过滤条件

元数据过滤可以在相似度排序前缩小搜索空间，例如：

```text
tenant_id = 当前租户
department in 用户可访问部门
effective_from <= 查询日期
effective_to > 查询日期
language = zh-CN
```

业务过滤和权限过滤含义不同。前者改善相关性，后者是安全边界。权限条件必须由可信的服务端身份生成，不能直接接受模型或用户提供的过滤表达式。

过滤过严也会损失召回。故障分析时需要记录过滤前后的候选数量，以及候选被排除的原因。

## 候选集处理

初次召回通常返回比最终上下文更多的候选，随后执行：

1. 合并多路结果并去除同一个 chunk 的重复项。
2. 合并高度重叠的相邻片段，避免重复占用上下文。
3. 按权限、版本、时间和内容类型执行过滤。
4. 保留一定来源多样性，避免 Top-K 全部来自同一段文档。
5. 把候选交给重排器，选出最终证据。

相似度阈值不是跨模型通用的“相关性概率”。更换 Embedding 模型、距离度量或索引实现后，需要重新校准阈值。

## Reranker

Reranker（重排器）同时查看用户问题和每个候选片段，对“这个片段能否回答问题”做更精细的相关性评分。典型流程是先召回几十到几百个候选，再重排出少量片段：

```text
混合检索 Top-100 → Reranker → Top-8 → 上下文构造
```

重排通常提高前几条结果的精度，但增加延迟和调用成本。需要同时实验候选数量、最终 Top-K、重排模型和最大文本长度。重排器截断长片段时，也可能看不到真正相关的尾部内容。

## 常见故障定位

| 现象 | 优先检查 | 可能调整 |
| --- | --- | --- |
| 正确文档完全没有出现 | 解析、分块、过滤、召回 | 修复摄取；增加关键词或向量召回 |
| 找到主题相近但不能回答的片段 | 片段粒度、查询表达、重排 | 补充标题上下文；训练或更换重排器 |
| 编号和专有名词经常漏检 | 关键词索引、分词器 | 加入 BM25、同义词和字段搜索 |
| Top-K 都是同一段的重复内容 | overlap、去重和多样性 | 合并相邻片段；限制单文档候选数 |
| 多轮追问检索内容跑偏 | 查询改写、对话状态 | 生成独立查询并保留原始约束 |
| 增大 Top-K 后回答变差 | 上下文噪声、排序质量 | 加重排、阈值或上下文压缩 |
